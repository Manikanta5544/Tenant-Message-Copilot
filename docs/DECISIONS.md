# Decisions

Format: what, why. Anything that departs from the architecture PDF is marked **[deviation]**.

1. **Repo layout** follows the brief: `core/` (pure TS), `db/`, `app/`, `evals/`, `tests/`, `docs/`.
2. **Local DB driver.** Neon hosts use `@neondatabase/serverless` (Pool over WebSocket); any other host uses `node-postgres`. Same SQL and the same transaction-first `set_config(..., true)` path. Needed because Docker has no daemon in the build environment and the Neon driver cannot talk to plain Postgres.
3. **Inbox scope [deviation, minimal].** The PDF binds every run to one resident, but the manager inbox must list all residents. Added `app.view = 'inbox'`: read-only, organisation-wide SELECT on `residents`, `messages`, `runs`, `trace_events` only. It is set by server code, never by a request or the model. Leases, clauses, payment events and the ledger stay strictly resident-scoped. All writes require the resident scope.
4. **Custom messages.** The picker chooses a resident from the seeded inbox; the composite foreign key keeps it inside the server-fixed organisation.
5. **`schema_migrations`** is migration bookkeeping, not a twelfth domain table. Rate limiting uses `runs.visitor_hash`.
6. **Owner role.** Migrations and seed run as an owner with BYPASSRLS locally (`copilot_owner`); `FORCE ROW LEVEL SECURITY` is still set so a non-bypass owner is also bound. Neon's default owner role behaviour is **unverified** until credentials exist.
7. **Balance view.** `lease_balance` groups ledger entries by lease, date and type (`security_invoker`). Balance as of a date is the sum of its rows up to that date; TypeScript derives the same figure from raw entries and the two must agree.
8. **Clause validity.** A clause applies on date d when `effective_from <= d` and (`effective_to` is null or `d < effective_to`), matching Postgres half-open `daterange`.
9. **Duplicate rule.** An event with the same organisation, reference and state as an earlier one is stored with `is_duplicate = true` and cannot be posted.
10. **Inbox labels.** Category and urgency come from a run, never hand-labelled; unprocessed messages show "Not processed".
11. **Layer 3 outcomes [interpretation].** The PDF's layer table says layer 3 failure = "block the draft and log a critical incident"; its pipeline text says a draft that fails verification "returns once with the reason" and a second failure escalates. Reading: a TypeScript/SQL balance disagreement is an application fault, so it blocks with a critical incident and no retry; stray digits, currency, number words or months in model text are a model slip and get the one retry. Neither can reach a tenant. If the intent was "block on digits too", this is the one line to change (`core/verifier.ts`, layer 3).
12. **Guard scope.** Number words cover English, common Hindi/Hinglish and Telugu transliterations plus Devanagari and Telugu script. Left out on purpose: "do" (English word), "first" and "second" (ordinary prose), ambiguous short month forms ("may", "march" match only when capitalised). All of these are listed as known gaps; the semantic layer and adversarial cases cover them.
13. **Time zone.** Payment event dates are read in Asia/Kolkata so "last week" and "yesterday" match what an Indian tenant sees.
14. **Golden-case schema.** Expected values are SQL references resolved from the `lease_balance` view over the owner connection (independent of the tool path). Extra field `forbidden.balance_paise` lets a case state a plausible wrong balance (for example a pending payment treated as settled) explicitly.
15. **Draft rendering.** A payment fact renders with its reference, date and state ("settled", "pending", "failed", "duplicate entry", "reversed"), so the state shown to the tenant comes from code, not model wording.
16. **Neon test.** The pooled-connection isolation suite runs automatically when `DATABASE_URL_APP` is a `*.neon.tech` URL; otherwise a warning marks it unverified.
17. **Process correction.** The PDF was read in full only after phase 2 (the brief said read it first). Phase 1-2 work was reconciled against it afterwards: tables, ledger semantics, RLS, six layers, route table, tool allowlists, tier-1 case split (8/6/6) and endpoints all match. Entry 11 above was reworded because it had cited the PDF before I had read it.
18. **LLMProvider return shape [deviation, minimal].** The PDF's interface returns the parsed value. Ours returns `{ value, usage }` (unvalidated `unknown` value, validated by the pipeline's layer 1) so every call can be traced and costed, as the PDF requires for trace rows.
19. **lease_term facts.** The PDF builds them from structured lease fields, not from a tool. The pipeline adds them for lease questions and fee-waiver requests; there is no fifth tool.
20. **One tool round.** The PDF allows up to two rounds and four calls. The pipeline plans all calls from triage in one round (at most four); a second round is never needed with four fixed tools. Allowlist violations are rejected and logged.
21. **Clause conflict heuristic.** Two or more retrieved clauses with different numbers and comparable full-text rank (at least 60% of the top rank) are treated as possibly conflicting: holding reply, needs_review.
22. **Balance snapshot.** Ledger lines and the `lease_balance` sum are read in a single SQL statement (one snapshot), so a concurrent posting cannot cause a false TS/SQL mismatch.
23. **Per-call transactions.** Model calls can take seconds, so no transaction is held across them. Every store call opens its own short transaction with the scope set first.
24. **Mock prices.** The mock provider reports model names `mock-*` priced like the real models, so budget logic is exercised without pretending a real model ran.
25. **No fabricated recordings.** Replay fixtures can only be produced by a live run. Until one exists, `eval:replay` says so and exits non-zero instead of inventing results.
26. **Free-tier / non-Anthropic LLM [deviation from the PDF's stack row, requested by the owner].** The PDF names `claude-haiku-5-5` / `claude-sonnet-5-5`. The owner will not use an Anthropic key, so the live backend is an OpenAI-compatible provider (`core/providers/openai-compat.ts`; Groq by default, also OpenRouter, Together, Gemini's OpenAI endpoint, Ollama). The `LLMProvider` boundary is unchanged, the Anthropic provider is kept behind `LLM_PROVIDER=anthropic`, and nothing else in the pipeline knows which backend runs. Structured output uses JSON mode plus the schema in the prompt; every output is still re-validated by layers 1-3. Models and prices come from `LLM_*` env vars (free tier = zero cost, so the budget cap protects nothing there; the per-visitor rate limit does). **Neither backend has been run against a live hosted model here.**
27. **Conflict heuristic is deliberately cautious (measured).** Clause conflict is detected by comparable full-text rank (>= 60% of the top). Measured on the seed: true conflicts (Vikram, clauses 7 and 12) have ratios 0.62-0.76, while an incidental match (Lakshmi's due-date question also matching the late-payment clause) has 0.71 and up to 0.92. `ts_rank` on short clauses cannot separate them, so no threshold removes false positives without missing true conflicts. A missed conflict is worse than an unnecessary review, so the threshold stays and false positives cost a holding reply (case `lease-03` fails on this today). The intended refinement is the live semantic layer; unverified.
28. **Open S0-class finding (abs-05).** "The lift has been out of order... how long will the repair take?" retrieves the in-premises maintenance clause (it matches on "repair"), and a draft that quotes its 24-hour / 7-day terms would be an unsupported claim. Only the semantic layer can catch this; the mock's check always says "supported", so the case fails on the mock with S0 and is **left failing**. Re-run it with a real model before relying on the system. No deterministic guard was added: a common-area keyword rule would encode an assumption about every customer's leases.
29. **Mock tier-2 results are informational.** The mock has crude intent and query heuristics (it flags "ceiling fan" as urgent, has no Hindi/Telugu query mapping). Its tier-2 failures are mostly mock limits and the pipeline failed safe to holding replies. The mock was not tuned to pass them, since that would make the number meaningless.
30. **Idempotency conflicts.** Reusing a key for another message or resident returns 409; RLS hides the other run, so nothing about it is revealed. (Found by calling the API; fixed and tested.)
31. **Review fixes (external review, 21 Nov 2026).** Groq's own deprecations page (fetched 21 Nov 2026) lists `llama-3.1-8b-instant` and `llama-3.3-70b-versatile` as shut down 16 Aug 2026 (replacements `openai/gpt-oss-20b`, `openai/gpt-oss-120b`). Defaults are now those two. They are the only IDs I could confirm from documentation, **not** from a live `/models` call on a key: `npm run models` and `/api/demo/status` check each configured ID against the key's model list, and `npm run eval` refuses to start if one is missing. Decision #26's "Llama" wording is superseded.
32. **Reasoning models and token caps.** gpt-oss models may count hidden reasoning tokens against `max_tokens`. `LLM_REASONING_EFFORT` (sent as `reasoning_effort` only when set) and `LLM_OUTPUT_HEADROOM` (added to each step's cap) exist for this; `.env.example` sets low effort and 1000 headroom. Whether the endpoint honours them is unverified until the first live call.
33. **One bounded retry on 429/5xx** for both HTTP providers (Anthropic via SDK `maxRetries: 1`), honouring `Retry-After`, capped at a third of the step timeout. Tested against a stub (429->200, 503->200, give-up, no retry on 400). Not tested against a real throttled endpoint.
34. **Eval validity.** A run where more than 10% of cases end in fallback or run error is INVALID: gate fails, nothing is saved, so it can never become a baseline. Reproduced the reviewer's all-failure probe in a test. Live runs pace `EVAL_PACE_MS` (default 2000 ms) between cases.
35. **Budget day and run cap.** The budget day is the real UTC date (`budgetDay()`); `DEMO_AS_OF_DATE` only drives lease and ledger logic. `budget_days.runs_used` plus one conditional upsert enforces `DEMO_MAX_RUNS_PER_DAY` (default 150), tested with 20 concurrent requests against a cap of 7. With free models the cost cap is inert (cost 0); the run cap is what protects quota.
36. **Abuse surface.** Visitor = salted hash of the IP only (the User-Agent is caller-controlled). Hourly limits on runs and on custom messages are checked under a per-visitor advisory lock inside the inserting transaction, so concurrent bursts cannot overshoot and a rejected run leaves no row. Live messages are visible only to the visitor who wrote them (migration 0006 adds `messages.visitor_hash`). Residual risk: one visitor behind many IPs; a real deployment needs auth.
37. **Retrieval adjudication replaces the rank-ratio conflict heuristic.** After retrieval one structured call (stronger model) returns `relevant_ids / conflict / sufficient`. It may only remove clauses or raise a review flag, never add evidence; invented ids are ignored; no relevant clause or `sufficient=false` gives a holding reply; a malformed answer or provider error fails safe (two different clauses are held for review). `CLAUSE_CONFLICT_RATIO` is deleted. **The mock adjudicator reproduces the old heuristic, so mock results are unchanged (lease-03 and abs-05 still fail there); whether a real model fixes them is UNVERIFIED.** Supersedes #27/#28's "intended refinement". Cost: one more call per clause question (~3000 input tokens worst case).
38. **Guard determiners.** `one`, `once`, `ek`, `एक`, `ఒక` are ordinary words ("once the payment clears", "no one", "ek manager") and are allowed unless they quantify time, money or a count ("one week", "ek din", "once a month"). Larger number words, digits, currency and months stay blocked. Promise phrases ("tomorrow", "by evening", "kal tak") are now listed as unsupported in the semantic prompt (PROMPT_VERSION v2).
39. **Keyword floors.** `act as` now escalates only when followed by a manager/admin/owner/landlord role; `room N` is no longer a unit mention (a bare number is not evidence of another resident; flat/apartment/unit still are). Known remaining noise: "fire safety certificate" is flagged urgent (review only); "terminate my lease" goes to eviction (cautious on purpose).
40. **Polling instead of SSE.** `POST /api/runs` returns 202 with the run id at once and finishes the pipeline in `after()`; the UI polls `GET /api/runs/:id` every 700 ms, and events are persisted before the next step so the trace fills in live. This is not SSE (Tier 2 in the PDF); it was skipped, not forgotten. Stale `running` runs are marked failed after 90 s.
41. **Database robustness.** Pool `error` handlers (idle-client errors no longer crash the instance); a client whose ROLLBACK or write failed is destroyed (`release(true)`); a trace event is one statement and one round trip (scope set in a CTE the INSERT reads from; RLS rejection tested). Not yet measured on Neon.
42. **Replay keys** hash the prompts and output schemas (`PROMPT_FINGERPRINT`), so editing a prompt without bumping the version can no longer serve stale recordings. `vercel.json` removed (routes export `maxDuration`). `MAX_TOOL_ROUNDS` removed: one planned round, as #20 says; the constant was never used. ESLint was tried and abandoned: `typescript-eslint` does not support TypeScript 7; `noUnusedLocals` in `tsconfig.json` catches unused imports instead.
43. **Lock-report fixes.** (a) Text after a quoted clause loses a leading punctuation mark in `renderDraft`, so a model's ". Next sentence" cannot show a stray period; tested. (b) The Evals headline is always the latest valid *critical* (tier 1) run, preferring live, then replay, then mock; tier 2 runs are saved only with `--save-extended`, are labelled informational, and baselines are compared within the same tier (a bug: they were compared by case count). The mock all-50 run still fails its gate (`abs-05`); it is documented, not hidden, and not the headline. (c) The mock is free by default (`priced: true` only in budget tests), so a mock demo can never spend the budget. (d) `/api/demo/status` caches the provider model list for 60 s. (e) Per-visitor daily run cap (`RATE_LIMIT_PER_DAY`, default 40) so one visitor cannot consume the shared daily cap; tested. (f) `/api/ready` also checks `VISITOR_SALT` (production) and that live mode has a key; model availability stays on `/api/demo/status` so a provider outage cannot flap readiness. (g) `.env.example` starts in `PROVIDER_MODE=mock`. (h) Remaining `any` types removed from tools, store, trace UI and run views. (i) UI: one "not processed" chip, a single combined badge on phones, amber "runs left" before red "limit reached", the failed-run banner has its own "Generate again", and the poll waits 100 s so the server's 90 s stale rule reports a killed run as failed.
44. **D1 Mode policy.** `core/env.ts` rejects `PROVIDER_MODE=mock` when `NODE_ENV=production` (error names decision D1). The default in production is `live`. `/api/ready` returns 503 with the reason, API routes answer 503 "maintenance", and the root layout renders a maintenance page, so a labelled-mock system is never shown on a public URL. Mock and replay stay for tests, CI and explicit local use.
45. **D2 Security headers.** `proxy.ts` (Next 16) sets a per-request nonce CSP (`script-src 'self' 'nonce-…' 'strict-dynamic'`, no `unsafe-inline` for scripts), `frame-ancestors 'none'`, `object-src 'none'`, `base-uri`/`form-action 'self'`, `connect-src 'self'`, plus nosniff, Referrer-Policy, Permissions-Policy, X-Frame-Options, HSTS (production) and `no-store` on `/api/*`. `style-src` keeps `'unsafe-inline'` (Tailwind and next/font inject inline styles): a documented residual risk. Because the nonce is per request, pages render dynamically. The provided `next.config.hardened.ts` was not in the repo, so the header set was written from the brief.
46. **D3 Visitor-scoped runs.** `npm run seed` creates baseline runs (`visitor_hash IS NULL`) through the configured provider for the five scenarios. The inbox shows a visitor's own latest run for a message, else the baseline; a visitor's run never changes what others see. `GET /api/runs/:id` is by exact run id, so no selection logic was needed there. Index added in migration 0008; RLS policies unchanged.
47. **D4 Review actions.** Migration 0007 adds `review_actions` (approved / edited / regenerated), strict-scope RLS, SELECT and INSERT grants only, and triggers that reject UPDATE, DELETE and TRUNCATE for every role. `POST /api/runs/:id/review` is Zod-validated, idempotent and capped per visitor. An edited reply must clear the guard (no new numbers, dates or amounts; evidence-rendered values from the original draft are allowed) and a promise check. Rows carry the visitor hash and the app filters history by it; the database enforces organisation and resident scope only.
48. **D5 No authentication in the demo.** Capability URLs only; accepted risk in NOTE.md.
49. **D6 One configuration schema.** `core/env.ts` validates every variable (types, ranges, production rules) lazily, so `next build` needs no secrets. `scripts/lint.mjs` forbids `process.env` outside it (scripts and evals excepted).
50. **D7 Observability.** One JSON log line per run (never message text, IPs or keys), `/api/health` vs `/api/ready`, `Server-Timing` on `GET /api/runs/:id`. Client-side errors show a local reference id in the console; server errors show Next's digest, which is logged next to the error.
51. **Rate-limit identity.** `x-forwarded-for` is trusted only with `VERCEL=1` or `TRUST_PROXY=1`; otherwise requests share one conservative bucket, because the App Router exposes no socket address (deviation from "key on the socket address").
